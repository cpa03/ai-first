## Findings

### 1. Export Connectors Missing Timeout Protection (P1)

**Issue**: Export connectors (GitHub Projects, Trello, Notion) use raw `fetch()` calls instead of `fetchWithTimeout()`, which means they don't have timeout protection.

**Evidence**:

- `src/lib/export-connectors/github-projects-exporter.ts`: 10+ raw fetch calls
- `src/lib/export-connectors/trello-exporter.ts`: 7+ raw fetch calls
- `src/lib/export-connectors/base.ts`: Already imports `resilienceManager`

**Impact**: External API calls to GitHub/Trello/Notion could hang indefinitely, causing:

- Memory leaks from unresolved promises
- User-facing timeouts without proper error messages
- Resource exhaustion under load

**Recommendation**: Replace raw `fetch()` calls with `fetchWithTimeout()` in all export connectors.

### 2. Analytics Fire-and-Forget Calls Missing Error Handling (P2)

**Issue**: Analytics calls in `src/lib/analytics.ts` use fire-and-forget `fetch()` without proper error handling or timeout.

**Evidence**:

- Line 346: `fetch(\`${host}/capture/\`, { ... })` - no .catch()
- Line 385: `fetch(\`${host}/capture/\`, { ... })` - no .catch()

**Impact**: Unhandled promise rejections could cause:

- Console errors in production
- Memory leaks from unresolved promises
- Unreliable analytics data

**Recommendation**: Add `.catch()` handlers to fire-and-forget analytics calls.

### 3. Database Service Single Responsibility (P2)
